# 云端术语热词

## 在软件中编辑

刷新网页后，点击右上角“会议热词”。主控台、单向字幕页和双栏监看页均提供此入口。
选择“中译英”或“英译中”，点击“添加热词”，填写原词及指定译法。
已有词条可以直接修改或删除，最后点击“保存并应用到云端”。
保存只更新所选方向，保留另一方向和本地纠错词表；关闭后再打开仍会读取已保存内容。
更新会短暂重连翻译会话，建议在发言间隙操作。
窗口会分别提示本地保存结果与云端确认结果；出现“云端已确认”才表示云端已接收词库。

## 接入说明

千问实时翻译通过 `session.translation.corpus.phrases` 接收原词与指定译法。
中译英通道使用 glossary.json 的 `terms_zh_to_en`，英译中通道使用 `terms_en_to_zh`。
`asr_fixes` 仍用于本地同音字纠错，不作为翻译词对上传。此功能不等同于独立的 ASR 声学热词加权。

例如在 glossary.json 的相应词表中添加：

```json
{
  "terms_zh_to_en": {"提示词工程": "Prompt Engineering"},
  "terms_en_to_zh": {"Prompt Engineering": "提示词工程"}
}
```

上面仅为格式示例；编辑现有文件时保留其他词条。
保存后重启后台，或将完整更新词表通过 POST /api/glossary 提交。
接口更新会保存词库，并自动重连受影响的千问会话、发送新词表，无需重启软件。
当前实测服务拒绝已开始会话的再次 session.update，因此更新时会短暂停顿；建议在发言间隙更新。
每个方向的新词表替换旧词表；传空对象会在新会话中清空该方向的云端词表。
断线重连时会重新发送当前词表。

系统配置里显示每个方向发送的术语数量和云端确认状态。
GET /api/meta 的 cloud_status 同样提供 corpus_status 和 cloud_phrases_count。
confirmed 表示服务端回传的词表与当前词表一致；sent/pending/unconfirmed 不表示已经生效。
云端确认配置不保证每次识别或翻译都严格使用指定术语，实际效果取决于模型与音频。
仅接入千问实时翻译的上述参数；Gummy 当前返回 Model not exist，未声称它支持同样的注入路径。
